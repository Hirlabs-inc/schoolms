SCHOOL MANAGEMENT SYSTEM - TECHNICAL DOCUMENTATION
==================================================

1. SYSTEM OVERVIEW
------------------
This School Management System is a modern, web-based application designed to manage academic processes including student enrollment, course management, attendance tracking, and examination grading. It is built with a focus on performance, security, and user experience.

2. TECHNOLOGY STACK
-------------------
- **Framework**: Next.js 16 (App Router)
- **Language**: TypeScript
- **Styling**: Tailwind CSS v4 + Radix UI Primitives
- **State Management**: React Context + LocalStorage (for caching)
- **Database**: Supabase (PostgreSQL)
- **Authentication**: Supabase Auth
- **Icons**: Lucide React
- **Forms**: React Hook Form + Zod Validation
- **External APIs**: TextBee (for SMS notifications)

3. PROJECT STRUCTURE
--------------------
/app                -> Next.js App Router pages and layouts
  /admin            -> Admin-specific routes (User mgmt, Classes, Promotion)
  /teacher          -> Teacher-specific routes (Attendance, Exams, Results)
  /student          -> Student-specific routes (My Results, Attendance)
  /login            -> Authentication entry point
/components         -> Reusable UI components (shadcn/ui inspired)
/contexts           -> Global state providers (UserContext)
/lib                -> Core logic and utilities
  api.ts            -> Supabase API abstraction layer
  types.ts          -> TypeScript interfaces for domain models
  sms.ts            -> SMS gateway integration logic
  storage.ts        -> Legacy/Fallback local storage logic
/supabase_schema.sql -> Database schema and RLS policies

4. DATABASE ARCHITECTURE (SUPABASE)
-----------------------------------
The system uses a relational database model on PostgreSQL.

Key Tables:
- **profiles**: Extends `auth.users`. Stores role (ADMIN, TEACHER, STUDENT), names, and email.
- **students**: Links to `profiles`. Stores academic info (studentNumber, classId, parentPhone).
- **teachers**: Links to `profiles`. Stores staff info (department, specialization).
- **classes**: Lookup table for grade levels (Grade 1 - Grade 12).
- **courses**: Subjects linked to classes and assigned teachers.
- **exams**: Assessment records linked to courses.
- **exam_results**: Grades linked to exams and students.
- **attendance**: Daily records for students and teachers.

Security:
- **RLS (Row Level Security)**: Strictly enforced.
  - Admins: Full access.
  - Teachers: Can view/edit data related to their duties.
  - Students: Read-only access to their own records.

5. AUTHENTICATION & AUTHORIZATION
---------------------------------
- **Auth Flow**: Managed via Supabase Auth.
- **Role Management**: Custom `role` field in `profiles` table.
- **Protection**:
  - Middleware (not explicitly seen but implied/standard in Next.js).
  - `auth-guard.tsx`: Client-side component to protect routes based on user roles.
  - RLS Policies: Database-level protection against unauthorized access.

6. KEY MODULES & FEATURES
-------------------------

A. User Management (Admin)
   - Create users with specific roles.
   - Automatically generates related records (Student/Teacher tables) upon profile creation.
   - Handles password resets and updates.

B. Academic Structure
   - **Classes**: Pre-seeded (Grade 1-12).
   - **Courses**: Automatically generated based on curriculum (Primary vs. Secondary subjects).
   - **Assignment**: Teachers are assigned to specific courses.

C. Examination System
   - Teachers create exams for their courses.
   - Grading system supports marks, grades, and remarks.
   - Automated calculation of pass/fail status.

D. Attendance & SMS
   - Teachers mark attendance (Present, Absent, Late, Sick).
   - **Integration**: TextBee API is used to send SMS notifications to parents when a student is marked ABSENT.
   - Logic located in `lib/sms.ts`.

E. Student Promotion
   - Logic to promote students to the next grade level.
   - Validates if the student has passed required courses before promotion.

7. MAINTENANCE & UPGRADE GUIDE
------------------------------

A. Adding New Roles
   1. Update `UserRole` type in `lib/types.ts`.
   2. Update database check constraint on `profiles.role`.
   3. Update RLS policies in Supabase to define access for the new role.

B. Modifying the Curriculum
   1. Update `lib/constants.ts` for static definitions.
   2. If regenerating courses, modify the PL/pgSQL block in `supabase_schema.sql` or create a migration script.

C. SMS Gateway Changes
   - The SMS logic is isolated in `lib/sms.ts`.
   - To switch providers, update the `sendSMS` function and environment variables.

D. Performance Optimization
   - The `UserContext` currently implements a "stale-while-revalidate" strategy using LocalStorage.
   - For high-scale, consider implementing React Query (TanStack Query) to replace the custom caching logic in `api.ts` and contexts.

E. Deployment
   - Ensure all `NEXT_PUBLIC_` environment variables are set.
   - Run `supabase db push` or execute `supabase_schema.sql` to set up the production database.
   - The app is static-export compatible but relies on dynamic API routes for some features, so a Node.js environment (Vercel/Netlify) is recommended.

8. KNOWN LIMITATIONS / TODOs
----------------------------
- **Hardcoded Subjects**: Subject lists are currently defined in SQL/Constants. Moving this to a dynamic table would allow Admins to manage subjects via UI.
- **SMS Error Handling**: Currently logs to console. A retry mechanism or admin alert system could be added.
- **Complex Grading**: Currently supports simple marks. Weighted averages or GPA calculations would require schema updates.

9. ENVIRONMENT VARIABLES
------------------------
Required variables in `.env.local`:
- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `NEXT_PUBLIC_TEXTBEE_API_KEY` (For SMS features)
